## 3. 与核心原则一致、故未按「字面」采纳的建议

### 3.1 「旧路径将在 v3.0 移除（预计 2026 Q3）」类表述

- **未写入 README。**  
- **原因：** [CORE_PRINCIPLES.md](CORE_PRINCIPLES.md) 强调**协议优先**与可预期性；**未立项的移除日期**若写进文档会变成虚假承诺。当前策略在 README 中写清：**无承诺下线日期**；若废弃，会通过发行说明与 `LEGACY.md` 公告。  
- **与 LEGACY.md 一致**：旧路径「过渡期」可用，新集成走继任路径。

### 3.2 错误码「完整」列表与「每个码的 HTTP 固定表」

- **策略：** 在 AI_PROTOCOL 提供 **常见** 表 + **非穷举**声明；运行时以 **`error.code` + `message`** 为准（§1 协议优先）。  
- **原因：** 代码库中错误码分散（Vision、OCR、裁剪等），强行维护「绝对完整且 HTTP 永不变化」的表易与实现漂移，**违背**「文档与实现一致」的初衷。

### 3.3 浏览器 / 微信行的性能数字

- **已采用「经验表 + 非 SLA + 场景说明」**，**未**写入精确到个位数的 token 统计（评审亦未提供可复现基准）。  
- **与原则 2/3 一致**：主路径仍是 UIA；浏览器一行强调**更合适的自动化栈**，避免读者误以为本服务是通用浏览器驱动。
